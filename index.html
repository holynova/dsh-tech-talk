为什么需要 Harness？别再魔改“精装房”

  • 发动机 vs 底盘：模型负责思考，Harness 负责把能力安全接进工程环境
  • 痛点 1（换底座）：本地 Bash 切公司 Docker 沙箱，牵一发动全身
  • 痛点 2（管边界）：工具输出含密钥需打码，多数 Hook 只能看不能改
  • 痛点 3（改循环）：ReAct 换 PTC / Plan-Execute，只能 Fork 魔改源码
dsh 的目标：不做改不动的精装房，做一套连承重墙都能热插拔的底盘。

核心理念：什么是真正的“万物皆插件”？

原理一：Cordis 内核——热插拔为什么不漏内存？

secret-guard.ts TypeScript 
import type { Context } from '@deepseek-ai/cordis'

export const name = 'secret-guard'
// 1. 空间组合：声明硬依赖，未就绪自动挂起等待
export const inject = ['tools', 'approval']

export function apply(ctx: Context) {
  // 2. 时间组合：副作用绑定到 ctx 作用域
  ctx.effect(() => {
    const timer = setInterval(syncRules, 60_000)
    // 插件卸载 / 热重载时自动逆序执行回收
    return () => clearInterval(timer)
  })

  // 事件监听同样可逆，绝不留“幽灵 Listener”
  ctx.on('tool/after', redactSecrets)
}
  • 空间组合（inject）：无需操心启动顺序，条件齐备自动挂载
  • 级联安全：底层服务卸载，上层依赖插件自动退场，不悬空
  • 时间组合（ctx.effect）：类比 React cleanup + RAII
  • 热更新无泄漏：所有副作用按逆序自动回滚，一字节不留

原理二：三角色接缝——换沙箱怎么一行不改工具代码？

点击现场热切换 Provider 实现：
当前激活：dsh-bash-local — 命令在本机运行；切换至 dsh-bash-sandbox 时，左侧 dsh-tool-bash 零修改。
  • Definition（契约）：只定义接口，不含实现
  • Provider（实现）：按环境自由替换后端
  • Consumer（消费）：暴露给 LLM 的工具层
  • 适用面极广：Shell、文件读写、压缩策略全走接缝

双平面隔离：全局共享资产 vs 会话瞬态边界

  • Host Plane（进程级）：管模型、日志、沙箱与注册表
  • Agent Plane（会话级）：按 Preset 挂载人设与工具
  • 后置 Hook 可改写：直接脱敏或截断工具输出
  • 统一审批栈：自定义策略直连 ctx.approval

原理三：Session Log 为唯一真相 + 影子压缩

切换视角：
  • 唯一真相：只追加事件流（JSONL / SQLite），类比 WAL
  • 动态投影：LLM 消息、UI 时间线均由 Log 派生
  • 低成本 Fork：任意事件索引分叉探索，完整可回放
  • 影子压缩：表面折叠摘要，底层不删记录、不毁缓存

核心全流程：一条指令的端到端流转

  • 进程解耦：stdio JSON-RPC 天然支持跨语言 SDK 与崩溃隔离
  • 循环可换：把 dsh-agent-loop 换 PTC 或多 Agent，底层全复用
  • 处处有挂点：上下文、工具、审批、输出改写与 UI 均可插件介入

落到代码：写一个 dsh 插件长什么样？

index.ts TypeScript · 16 Lines 
import type { Context } from '@deepseek-ai/cordis'
import Schema from '@deepseek-ai/schemastery'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'metrics-inspector'
export const inject = ['tools', 'approval']
export interface Config { endpoint: string; strict: boolean }

export const Config = Schema.object({
  endpoint: Schema.string().required(),
  strict: Schema.boolean().default(true),
})

export function apply(ctx: Context, cfg: Config) {
  ctx.tools.register(defineTool({
    name: 'query_metrics',
    parameters: Schema.object({ svc: Schema.string() }),
    execute: ({ svc }) => fetchMetrics(cfg.endpoint, svc),
  }))
}
  • inject：声明服务依赖，Cordis 自动排布加载时机
  • Schema：配置自动校验，Web 端同步生成配置表单
  • defineTool：自动校验模型入参，直接暴露为工具
  • apply(ctx)：副作用绑定作用域，热卸载自动清理

现场高频 Q&A 速查

1. 这跟 MCP 有什么区别？
层级不同、完全互补。MCP 是“USB 外设协议”，只管接入工具/数据；dsh 是“微内核主板”，MCP 只是 dsh 里可接入的一类插件，dsh 还负责 Loop、Session 压缩、审批、沙箱和 UI。
2. 跟 Claude Code / LangGraph 怎么选？
Claude Code 是极致精装成品；LangGraph 偏有向图工作流编排；dsh 主打“可深度二次开发、热组合的 Agent 运行时底盘”，适合内网沙箱、私有审批与团队插件沉淀。
3. 全插件化会不会难 Debug？
两重保障：① inject 显式声明依赖，启动期立刻定位缺失服务；② Append-Only Session Log 完整记录每步事件，出问题直接回放复现。
4. 影子压缩会丢上下文吗？
摘要视图本身有损，但底层原始事件从未物理删除，审计、调试或按需回查原始片段都 100% 保留。
5. 只能用 DeepSeek 模型吗？
完全模型无关（Model-Agnostic），模型路由本身也是插件，支持 DeepSeek 原生以及 OpenAI / Anthropic 兼容协议端点。
